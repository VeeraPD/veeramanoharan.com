Alpine Skies: a flight sim that starts in under a minute

Problem statement

A browser flight simulator for quick sessions over the Swiss Alps.

Play it ↗

Problem

A quick flight should be easy to start

Casual aviation fans want a satisfying flight without a large download, specialist hardware or hours spent learning controls before they can enjoy a session.

Issue

Accessibility needs a reason to return

Fast loading alone does not create a compelling game. Players also need clear goals, manageable challenges and a progression path that fits short sessions.

Solution

Open a tab and take off

Alpine Skies brings Swiss Alps flying to the browser with guest play, missions by length, a difficulty ladder and a daily challenge. Cold load improved from 8.4 to about 4.6 seconds.

Decisions and trade-offs

Guest play and mission structure reduce the effort to start

01Guest start

Play instantly as a guest; save codes move progress across devices

Why: Sign-up friction kills first sessions.

Trade-off: Early email capture for growth

02Visual quality vs speed

Balanced visuals against frame rate on average laptops

Why: A beautiful game that stutters loses players anyway. This is the call behind the 8.4 s to 4.6 s load cut.

Trade-off: Peak graphics

03Retention loop

Daily Challenge, achievements, leaderboard, stars and coins

Why: New content is expensive to build; reasons to return are cheap. A bet, not yet measured: the 7-day return rate will test it.

Trade-off: Build time on new aircraft and maps

04Five modes

Flight School, Campaign, Free Flight, Quick Challenges, Daily Challenge

Why: Each mode served a different need. But it broke my own rule about the first 60 seconds: play-testing found the menus confusing. For new players this was a mistake.

Trade-off: A single polished mode

Execution

Play-test feedback shaped versions 1.15 through 1.23

I rebuilt the game on real terrain, the Bernese Oberland from swisstopo open data, tuned to run on laptop graphics. Play-testing then showed the menus and levels were confusing, there was not enough to do, and progress was not saved.

Versions 1.15 to 1.23 answered that with missions sorted by length, Flight School, a daily challenge, guest saves, a leaderboard and clearer in-flight guidance. I then added product analytics on the web build, and accounts, progress saves and the leaderboard in Supabase, so the next round is judged on what players do.

Experiment

Test whether a guided first flight improves mission completionPlanned

  • Hypothesis: dropping players straight into a 60-second guided flight raises first-mission completion.
  • Primary metric: share of new players who complete a mission in session 1. Guardrail: 7-day return rate must not fall.
  • Decision rule: ship the guided start if completion rises with no drop in return; otherwise keep the menu and test a shorter Flight School.
  • Traffic check first: if there are too few new players each week for an A/B test, compare the funnel before and after and run moderated play sessions instead. The result will say which method was used.

What I learned

Product constraints still need judgment when AI builds the code

AI coding tools sped up the build. The product decisions, scope and quality bar stayed mine.

My first-60-seconds rule was right, and I broke it with five modes. Writing the rule down is what made the mistake visible. Next: publish the player funnel, run the onboarding test, and try a fake-door test for cosmetic aircraft before building any.
